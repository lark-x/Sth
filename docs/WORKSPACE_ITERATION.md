# Sth 创作工作区迭代计划

更新于 2026-11-28。Sth 服务于用自然语言写日记、整理原文、推敲长篇的个人作者。作者可以在习惯的助手里交代想法，在网页上读稿、修订和选稿。换到另一个助手后，作品、出处、采用的版本和仍待商量的事都能接着用。

最小体验是一篇独立日记。复杂体验从一段原文或一个角色开始，经讨论产生不同讲法，作者选定一稿后编入章节。改变事件走向时另开 IF。两种体验共用作品、日记、角色、资料与故事模块，以及同一组可发现的业务操作。日常写作沿用当前对话的模型，点名方案或委托批量任务时才启动对应供应商。

### 本轮工作流程

本节按 2026-11-28 用户最新要求执行，取代此前的双子智能体讨论与单模型实施安排。当前主模型负责产品判断、计划、派工、集成和最终验收，也直接参与讨论。样稿先完成一轮评审，再将确定的布局用于 Vue 正式页面。

#### 模型与并发

| 职责 | 模型与强度 | 并发安排 | 工作范围 |
| --- | --- | --- | --- |
| 主代理 | 当前模型，沿用当前会话配置 | 1 个主会话 | 与讨论席共同判断，维护计划和设计约定，协调依赖、整合改动、亲自验收和交付 |
| 讨论席 | `chatflowsai/gpt-6.2-astra`，`xhigh` | 按阶段启用 1 个 | 产品取舍、视觉评审、架构边界和验收结论；提供推荐及理由，由主代理记录并执行综合推荐 |
| 常规实施组 | `xingchi/gpt-6.1-sol`，`xhigh` | 最多 4 个 | 已确定设计下的基础控件、样式、常规页面、文案与对应验证 |
| 复杂实施组 | `chatflowsai/gpt-6.2-sol`，`xhigh` | 最多 4 个 | 复杂布局状态、版本与采用逻辑、保存冲突、依据关联、宿主接续和困难缺陷 |

实施并发上限为 4 + 4。两组配额分别控制，依赖未就绪时保留空位。讨论优先放在派工前和阶段收敛时，用完关闭；如需与实施并行，先空出一个实施席，此时实施最多 7 席，使同时运行的子智能体仍不超过既有 8 个总上限。返修和独立复验同样占席，已完成的子智能体及时关闭。主会话不占子智能体名额。

每次派工记录供应商、模型路由和推理强度。模型调用失败时记录实际错误，继续可以独立进行的工作；该任务保留待处理状态，替换模型须有用户明确授权。启动成功、模型完成任务和最终验收分别记录。

#### 每阶段的执行顺序

1. **确认起点和作者路径。** 主代理记录包含上一轮成果的基线，建立本轮迭代分支。用同一篇《第三声以后》、同一版本与选段保存现状，日记和多章多稿样例使用隔离数据。先写清入口、操作、预期画面与失败恢复条件。
2. **讨论并记录推荐。** 当前模型先提出方案，Astra 从作者体验、视觉层级、实现边界和验收可行性提出异议或替代。主代理归纳综合推荐、理由、影响页面及可检验场景，按推荐执行。对已有明确要求直接落实；当新证据改变依据时再讨论。方案无法从现有证据确定时先做最小样稿或实验。只将确实缺失的信息、授权或用户专属选择交给用户。
3. **先确定共享规则，再派发独立任务。** 样稿评审通过后确定主题、布局、路由、版本和依据事件等接口。先用《第三声以后》走通“首页续稿 → 读旧版 → 查该版依据 → 回原段”，主代理并排查看首页、读稿和角色页的灰白层级、选中态、焦点及稿件身份，再铺开各域。每张任务卡包含目标、模型、依赖、允许写入的文件、复用接口、样例、验收条件和交付位置。一个文件在同一轮只设一个写入负责人，共享接口变更由主代理统一协调并通知依赖任务，仅暂停受影响的任务。
4. **隔离实现并交回证据。** 代码任务使用独立 worktree/分支；测试服务、端口、数据库及截图目录分别隔离。子智能体交回变更文件、提交或差异、已运行检查、截图和未解决问题。统一由主代理集成到本轮分支。常规任务可交叉检查，困难问题及关键状态由另一名 6.2 Sol 复核。
5. **在整合构建验收。** 每批合入后用相同中文样本核对受影响画面，主代理用 Playwright 从实际入口操作；阶段收敛时亲自查看四种宽度的截图，逐项对照设计要求。优先验收“首页续稿 → 查角色或原文 → 回原稿原段”和“章内新建 → 写作 → 保存重开”。功能通过、视觉达标和部署状态分别记录。实现者的自测作为证据，阶段完成由主代理复核决定。
6. **将问题回派并复测。** 记录稿件、修订、视口、构建版本、复现步骤、期望与实际结果。按难度回派；修复者交回复现与修正证据，另一席或主代理在整合构建重走原路径并补测受影响环节，截图重新生成。未达标的样稿先修正，尚未稳定的设计不继续铺到其他页面。
7. **汇报阶段结果并继续。** 每轮交付说明实际完成项、视觉与功能结果、剩余问题和下一批依赖。主代理按计划继续推进。最终记录代码提交号、浏览器构建与宿主安装包各自的摘要值，核对验收记录、GitHub 开发分支、本机 `9322` 实际提供的构建和最新安装包之间的对应关系，部署后重开相同作者路径复验。

全过程使用自动化浏览器和静态截图，不使用 Computer Use。本轮按浏览器截图验收；真实 iOS、WKWebView 和真人私聊列入后续设备阶段。以下截图清单适用于每轮整合构建。
