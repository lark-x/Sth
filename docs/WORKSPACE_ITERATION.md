# Sth 创作工作区迭代计划

更新于 2026-11-27。Sth 服务于用自然语言写日记、整理原文、推敲长篇的个人作者。作者可以在习惯的助手里交代想法，在网页上读稿、修订和选稿。换到另一个助手后，作品、出处、采用的版本和仍待商量的事都能接着用。

最小体验是一篇独立日记。复杂体验从一段原文或一个角色开始，经讨论产生不同讲法，作者选定一稿后编入章节。改变事件走向时另开 IF。两种体验共用作品、日记、角色、资料与故事模块，以及同一组可发现的业务操作。日常写作沿用当前对话的模型，点名方案或委托批量任务时才启动对应供应商。

## 当前起点

私有仓库 `lark-x/Sth` 的默认分支为 `main`，起点为 `ec1f1e4`。第一轮开发分支为 `feat/agent-workspace-onboarding`。本机作者工作区在 9322，已有带出处的日记、两种视角的成稿、IF 接续位置和场景插画。它们是升级与改版的真实回归样本。[原始四阶段计划](AI_NATIVE_ROADMAP.md) · [原文到故事的立项设计](RESEARCH_STORY_PLAN.md) · [现有作品与验收记录](ACCEPTANCE.md)

### 本轮工作流程

主代理用当前模型负责计划、派工、集成和最终验收。每个阶段都按下列流程推进，样稿先走完整轮，再将定下的布局用于 Vue 正式页面。

1. **确定起点和样例。** 主代理从包含上一轮成果的开发版本开本轮迭代分支，记录基线提交和本机预览版本，保留 `main` 基线。用同一篇《第三声以后》、同一版本与选段记录现版首屏，日记和多章多稿样例使用隔离数据。为当阶段写清作者入口、操作和预期画面。
2. **讨论有取舍的决定。** 对影响作者的选择，例如手机点开历史选段时显示什么、切稿时如何保留改动，由 Codex 原生 `gpt-6.2-sol` 与 `chatflowsai/gpt-6.2-astra` 分别以 `xhigh` 讨论。主代理记录推荐、理由及可检验的作者场景，按综合推荐执行。已定的布局和日常实现由主代理直接推进。
3. **分派互不冲突的工作。** 实现使用 `xingchi/gpt-6.1-sol`，推理强度 `xhigh`。同时运行的子智能体最多 8 个，讨论席计入总数。每项任务写明负责的文件、复用的业务接口和要交回的画面；资料库、编辑器、依据面板可分开实现，共用路由、样式与版本选择由主代理协调。合入当轮分支前核对各项改动。
4. **逐阶段看图并修正。** 主代理在整合后的同一构建上通过 Playwright 打开实际入口，按下方清单截图并亲自逐张查看。对选段偏移、切稿位置丢失或操作遮住正文等问题，记下稿件、视口和复现步骤，交回对应实现者；修正后重走原路径，重截受影响画面并对照。全程使用自动化浏览器与静态截图，本轮验收仅依据浏览器画面。
5. **汇报并继续迭代。** 阶段报告列明本次实现、已看截图、发现与修正的问题、剩余工作，并附可打开的样稿或页面。主代理按已定计划推进下一阶段。最终将通过截图验收的开发版本部署到本机 `9322`，重开同一稿件核对发布画面，交付分支与提交号、预览地址及前后对照图。真实 iOS 和真人私聊留在后续设备阶段。
