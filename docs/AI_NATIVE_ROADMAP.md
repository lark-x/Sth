# Sth AI 原生创作工作区 · 四阶段计划

四阶段的目标是让作者通过一次长期配对，在 Hermes 私聊里用自然语言完成从收集资料、讨论剧情到批量出图的全过程。换一个 MCP 客户端可以接着做，打开网页可以核对同一份正文、出处和任务进度。实施采用全新数据库，当前接口见 [前端与后端契约](FRONTEND_BACKEND.md)。

## 起点与设计约定

独立工程 Sth 默认运行在 `9321`。开发起点有 10 个作品、角色和日记操作。个人日记可以独立保存，角色日记能固定写作时的人设版本。配对码十分钟内领取一次，连接持续有效直至撤销。[启动与备份](../README.md) · [当前共享操作目录](../src/workspace.ts) · [适配器与验收环境](../adapters/README.md)

| 设计约定 | 开发时如何落实 |
| --- | --- |
| 网页与 AI 共享核心 | 每项面向作者的业务动作先进入操作目录，声明用途、输入、输出和错误。网页调用同一实现；Hermes 和 MCP 通过发现与调用使用它。网页路由、组件和样式可以独立重做。 |
| 一次连接覆盖个人工作区 | 作品是内容归属或引用对象。只有「加入某章」「列出某作品的场景」这类动作才需要定位作品；跨作品遇到同名对象时返回可识别的候选，由作者或已有上下文消歧。 |
| 换会话也能继续 | 对外使用稳定的资源 ID。引用保留具体修订和可读出处。写入返回持久回执，重试沿用原步骤，遇到并发修改返回当前版本，供重新读取和合并。 |
| 用业务开发验证扩展方式 | 资料模块先声明操作、数据迁移、资源类型和内部链接，并配契约测试。场景模块作为第二个使用者，检验哪些约定值得提取为公共代码。仅当新增传输方式或特殊交互时才扩展适配器。 |

## 第一阶段 · 创作资料与引用

**交付目标**：作者只提供一段设定，助手就能保存、找回原文、据此写日记，并回答「这句设定当时来自哪里」。

1. **建立新库并验证恢复。** 使用全新的 Sth 数据库建立模块结构，验证同版数据库重启与快照恢复后，正文、连接、回执和资源可继续读回。[数据库](../src/database.ts) · [Hermes 适配器](../adapters/hermes_plugin/personal_operations.py)
2. **交付可引用的资料。** 支持设定、灵感、摘录及其来源，允许个人独立保存和多个作品引用同一条资料。修订保留历史；日记保存所用资料的版本和原文片段，资料详情可反查使用它的内容。
3. **让 AI 找得到、读得准。** 提供创建、修订、按 ID 和版本读取、中文检索、列举引用和反向引用操作。先用真实中文样本检查标题、短词、正文片段和同名候选，在 SQLite 上实现可解释的关键词检索；根据漏检样本再决定是否补充分词或语义检索。
4. **最小网页。** 资料列表带搜索，详情可编辑、查历史、看出处；日记详情可打开当时引用的原文。资源链接由核心声明，适配器只接受服务认可的内部目标。

**作者验收**：在 QQ 说「记一条设定：北港末班渡船是晚上十点」，不选作品。接着说「找到北港的原话，用它写一篇日记」。从网页把资料改为九点，再用新会话查旧日记和写一篇新稿。旧日记应指向写着「十点」的旧版，新稿引用「九点」的新版，资料页能查到两篇日记。将同一资料用于另一部作品后，仍可回到同一个来源。

## 第二阶段 · 场景与候选稿

**交付目标**：只给一个角色就能开始讨论。作者能从几种讲法中选稿、编入章节、继续修改，也能另开一条剧情 IF 线。

1. **建立场景和章节。** 使用第一阶段的资源、修订和引用能力。场景记录出场角色、人设版本、资料出处及可选的时间地点。允许先创建独立场景，编入章节时再确定作品和顺序。
2. **支持讨论、写稿和采纳。** Hermes 可先建议时间地点和不同讲法，继续聊清楚后再生成候选稿。提供创建候选、对照、修订、按作者指令采纳、编排和读取当前采用稿的操作。采纳记录指向具体稿件版本，同时保存其余候选。
3. **区分讲法与剧情走向。** 同一事件换叙述视角时，在同一场景保存候选稿；「如果主角没有上船」这类改变事件走向的要求，可以从指定版本建立 IF 分支，记录分歧点，单独续写。
4. **最小网页。** 作品章节目录、场景详情、候选文本对照、采纳和来源链接。展示当前采用稿、其他候选和 IF 分歧点。

**作者验收**：在 QQ 说「用林岚写北港那一晚，先给我两种讲法」。聊完后要求「两种都写，第二稿收入第一章」。网页应能对照两稿、看到第一章的选稿及依据。换会话修改所选稿的结尾，再开一个「她没上船」的 IF；原章节仍能读到作者选定的走向，第一稿和 IF 都可单独找回。

## 第三阶段 · 模板与生成配置

**交付目标**：日记、短故事、剧本和分镜都能按作者制定的结构生成；作者能查清某份稿件采用了哪版模板，必要时再点名另一模型写对照稿。

1. **拆开三种可复用内容。** 内容结构定义字段、顺序和校验；写作要求定义视角、语气和约束；命名生成方案指定执行方、供应商、模型及可支持的参数。三者分别维护版本，可跨作品组合使用。用日记和分镜两种不同结构验证扩展方式。
2. **明确谁负责写。** 普通请求沿用当前 Hermes 对话写作，Sth 负责准备带版本的上下文、校验结构和保存。作者明确说「用某方案再写一版」时才发起单次委托。此阶段交付可用的单次委托；第四阶段复用它处理批量请求。
3. **保存实际生成记录。** 产物关联输入资料、人设、模板、写作要求、执行方案版本和结果。区分请求的模型与执行方实际回报的信息；取不到的字段显示「未知」。校验失败返回具体字段供 AI 修正，保留此前已采纳的稿件。
4. **最小网页。** 模板及方案列表、版本编辑、结构预览、稿件生成记录。通过共享操作也能在私聊中完成创建、修改、选用和查阅。

**作者验收**：建一个四段日记模板，在两个作品复用。把模板改为五段，读回旧稿的四段模板，再用新版写一篇。明确指定一个已配置的命名方案写对照稿，核对实际执行记录、所用输入版本和两份独立结果。普通对话写稿应只产生本次对话的写作结果。

## 第四阶段 · 长任务与媒体

**交付目标**：一次交代多个场景后，可以离开聊天。稍后回来能看到每一项做到哪一步、哪些需要处理、图片存在哪里。

1. **交付持久任务。** 保存任务、逐项输入版本、步骤、输出与状态。创建、查进度、取消剩余项、重试失败项和读取结果都通过共享操作暴露。事务先保存待执行步骤，提交后由工作进程调用供应商；重启后按持久状态恢复。
2. **处理外部调用的不确定性。** 每个外部步骤记录稳定请求标识、上游任务号和可查的结果。优先使用上游幂等或查询能力；上游可能已经受理但无法确认时，把该项标为「待核对」并显示原因，暂停自动重发。取消时区分待执行与上游已受理的项，成功结果可继续读取。
3. **接通一个真实媒体供应商。** 从场景和资料生成构图候选，作者可在 QQ 或网页选择，助手提交生成、归档实际文件和可用参数，并回链到具体场景版本及作品。区分作者直接发起的请求与自主执行，按执行方式沿用对应预算规则。
4. **最小网页。** 任务列表和逐项详情、构图选择、取消与重试、媒体预览和来源。媒体文件与数据库一并纳入备份恢复验收。

**作者验收**：选五个场景、指定构图并启动一批任务。在隔离实例上中途重启，模拟一项失败和一项回执未知。回到 QQ 查进度，只重试已确认失败项；已成功项沿用原结果，未知项能看到核对入口。用真实供应商至少完成一张图，从 QQ 回执打开预览并回到对应场景。恢复备份后仍可打开图片。

## 开源参考与采用条件

| 阶段 | 可借鉴的具体做法 | 在 Sth 的落点 |
| --- | --- | --- |
| 公共适配层 | 工具发现、结构化调用和结果。[MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk) | 继续使用适配器已锁定的 `1.30.0`，用真实 stdio 客户端回归契约。业务规则归 Sth 核心。 |
| 创作资料 | 双向链接与从引用返回上下文。[Logseq](https://github.com/logseq/logseq) | 借鉴交互和引用关系，给 Sth 的原文引用增加明确的修订标识。 |
| 场景 | 故事选择和分支的表达。[ink](https://github.com/inkle/ink) | 借鉴分歧点与走向的表达，Sth 自身保存作者选稿、人设和资料引用。 |
| 模板 | 提示模板版本与生成追溯。[Langfuse](https://github.com/langfuse/langfuse) | 先在本地数据库留下可核对的模板版本和生成记录。 |
| 长任务 | 可恢复的工作流与外部活动边界。[Temporal TypeScript SDK](https://github.com/temporalio/sdk-typescript) | 参考恢复语义和故障用例，先验证本地数据库加工作进程能否满足单人使用。 |

每个阶段实施前，在对应任务里记录实际参考的版本、文件、许可证、运行依赖和替换成本；明确采用现有库、借鉴设计或自行实现的理由。按本阶段作者验收场景评估选型，开源项目的功能范围不决定 Sth 的交付范围。

## 阶段完成标准与开工顺序

1. **核心可独立验收。** 在隔离数据库上验证每项操作的输入输出、持久化、旧版读取、冲突和同一步骤重试。涉及外部调用的阶段补充失败和恢复样本。将已有作品、角色和日记纳入回归。
2. **AI 能端到端完成。** 给真实模型自然语言任务，让它自行发现、组合操作并读回已保存结果。换会话或换 MCP 客户端，按相同资源和版本继续操作。网页修改后让助手读回，反向也做一遍。
3. **逐渠道留下证据。** 核心测试、真实模型调用、MCP stdio、Hermes 模拟消息和手机 QQ 实测分别记录。手机验收使用已配对的私聊，核对回复、实际保存记录和可访问的链接；链接使用手机可达的网页地址。微信按相同用例单列实测结果，尚未实测的渠道标为待验。[手机链接配置](../README.md#手机链接)
4. **交付后再勾选阶段。** 记录验收版本、快照恢复结果、通过用例和待验证项。内容持久化、跨端读回或恢复存在缺口时，保留该项待办，让后续开发能从明确位置接手。

交付顺序从全新工作区、个人资料和日记引用开始，完成「十点改九点」验收。随后以场景和候选稿验证扩展方式，再引入模板和外部执行，最后实现批量恢复和媒体生成。
