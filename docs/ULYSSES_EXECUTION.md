## 已采纳的决策

- 当前模型与 Astra 讨论后，先完成全量基线再按受影响模块更新，治理范围由可复现问题决定。
- 主题先在首页、读稿、角色三页验证，共享变量和接口确定后再铺到其他页面。
- 章内创建独立验收创建成功、归章冲突和已输入正文并存的情况，重试应保留原场景、正文及他人最新章序。
- 历史选段直达与跨辅助页返回分别验证，证据跟随所读稿件修订；无关联时明确说明缺失。
- 列表真实摘要同时比较请求数，避免每个条目额外读取全文造成加载成本扩大。
- Astra 建议本轮保持现有公共 API。已采用稿用准确版本原文；未采用稿的摘要按可见条目渐进读取，并标明稿名和修订、与打开目标一致。原有全文搜索范围单独验证，尚未完成全文读取时不能宣称没有结果。冷首屏、滚动和冷搜索的请求成本分别比较。
- 修复者与复验者分开；未完成验证的变更不部署。

## 已接受的边界与终止条件

- L1 保留一项 P3：首次候选读取尚未完成时清除搜索，可能短暂显示“正在搜索正文…”，直到读取结束；不会误显示空库或错误创建入口。
- N2 使用经过校验的同源回链、原条目 token 与正整数深度恢复多跳。超时撤销当前条目的回退资格，下一次明确点击按 href 返回，没有定时自动跳转。人为把 history state 篡改成另一个范围内有效深度，仍可能落到其他历史条目；浏览器 History API 无法事先读取目标条目，未复现自然操作路径故障，本轮不新增历史台账。
- 真实 iPhone、WKWebView、真人 QQ/微信仍待设备阶段。本轮重验已安装 Hermes 的工具及合成 CLI/QQ/微信上下文；不把它写成新的真实模型或真人设备通过。真实 Codex/Antigravity 启动与登录可选测试的环境条件另列。
- Windows 浏览器多组联跑和一次手机采集出现原生退出。失败日志保留，最后按单组采集全部完成；通过组与失败组使用不同目录，避免覆盖失败证据。
- 高频作者路径、版本/依据正确性和明确视觉差距收敛后结束本轮。静态 Hermes 循环、无业务故障的目录结构或只降低重复计数的改造不排入本周期。
