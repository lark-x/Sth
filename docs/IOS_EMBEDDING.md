# 手机网页与 iOS 容器接入

Sth 网页是手机上的创作入口。未来的 iOS App 可在 `WKWebView` 中装载同一作者工作区。服务端 SQLite 保存作品和修订，域名决定打开哪个工作区。当前交付包含 Vue 移动布局、可直接打开的资源链接和浏览器回归。

本轮前端改版仅使用[浏览器截图验收](WORKSPACE_ITERATION.md#浏览器截图清单)。下文保留已做过的浏览器实验以及后续设备接入步骤。真实 iPhone Safari、系统中文键盘和 App 容器均排入后续设备阶段。

## 打开同一篇稿件

1. 在手机可以访问的 HTTPS 域名上部署工作区，将服务的 `STH_PUBLIC_ORIGIN` 设置为该来源并配置 `STH_WEB_PASSWORD`。反向代理保留 Host。Hermes 的 `STH_PERSONAL_OPERATIONS_PORTAL_ORIGIN` 使用同一入口。Mac 或 PC 的 `127.0.0.1` 在手机上会指向手机自身。[手机链接配置](../README.md#手机链接)
2. App 打开作者选择的工作区 URL。内部导航保留路径、查询参数及锚点。例如 `/diaries/<id>?revision=1` 是指定旧稿，`/diaries/<id>` 读取当前版本。系统返回手势先检查 `canGoBack`，有网页历史时调用 `goBack()`。外部引文交给系统浏览器。
3. 远程作者网页使用 HTTPS 和 HTTP Basic challenge。用户名是 `sth`。容器如选择代办登录，应在匹配工作区域名和服务器认证方式后请求作者凭据，并将保存决定交给作者。MCP/Hermes 的长期配对令牌仅由各自适配器使用。网页已通过同源 `/api/web` 调用共享核心，容器可直接加载服务端页面。
4. 上传角色图片、音频等文件时沿用网页的文件选择控件。页面上报告保存成功后再关闭编辑视图。容器被系统回收后，从原资源 URL 重开，已保存内容由服务读回。尚未提交的草稿恢复要按实际编辑器、系统终止与重启路径逐项检查。

### 通过 HTTPS 打开助手给出的链接

2026-11-27 在 Windows 上使用独立工作区、临时证书和仅本机可达的 HTTPS 反向代理检查这一流程。已配对的客户端创建第 1 版日记，Hermes 插件使用服务声明的结果字段和 `STH_PERSONAL_OPERATIONS_PORTAL_ORIGIN` 生成回复链接。代理保留请求 Host。浏览器打开该链接、编辑正文、保存后重开第 1 版，最后由原客户端读取最新版。

| 实际环境 | 结果 |
| --- | --- |
| Chromium，手机尺寸，按浏览器登录挑战提供凭据 | 未登录请求收到 HTTP 401 和 Basic 登录挑战。登录后读到原稿，保存为第 2 版，旧链接与助手分别读回各自版本。 |
| Windows Playwright WebKit，iPhone 13 参数，按浏览器登录挑战提供凭据 | 从链接可读日记正文。进入编辑页后，部分 POST 遇到 401，浏览器重送请求体时报 `Send failed since rewinding of the data stream failed`，编辑页加载失败。指定登录域名和省略域名限制均复现。 |
| 同一 WebKit 引擎，由测试客户端为该工作区预先附上凭据 | 从插件链接打开、编辑、保存、读旧稿和助手读回第 2 版均通过。此项验证了凭据随请求送达后的业务流程。 |

同机使用纯回环 HTTP、Basic 登录和两次顺序 POST 的最小对照，两次都返回 200。HTTPS 工作区中，先从站点首页登录、改用 Blob 或字节数组发送正文、改用 XMLHttpRequest 均未解决重送问题。另在全新会话中等受保护的目录 GET 完整返回 200，再放行首个业务 POST，仍在 401 后重送失败。

下一次真机验收先从助手的 HTTPS 链接登录，立即进入「编辑」，保存一句中文并关闭重开，核对第 1、2 版。记录设备、iOS 版本，以及失败请求的路径和状态码。桌面验收使用临时证书的浏览器测试例外。系统对正式证书的信任、Safari 的认证缓存与 iOS 中文键盘仍需在设备上检查。

WebKit 回归使用临时数据库和随机端口。安装匹配版本的 WebKit 并构建前端后运行以下命令。真实 iPhone 与实际 App 容器的验收分别记录，需填写设备、系统版本及宿主版本。

```sh
npx playwright install webkit
npm run build
node --test tests/mobile/webkit.test.mjs
```
