# 作者读写与审阅迭代

2026-11-28，用户在 Gemini 全文评审后授权持续推进，沿用 [既有工作流程](WORKSPACE_ITERATION.md#本轮工作流程)。起点为 `feat/unified-writing-ui` 的 `34d68b9f0dcb83fc801a2d0eb093e9f28a8f6016`，集成分支为 `feat/author-reading-review`。`main` 保留原基线。工作树已有的未跟踪 pnpm 文件不属于本轮。

## 范围与决策

Sth 是作者与多个 AI 助手共用的创作工作区。先完善默认读写界面及候选稿审阅，沿用网页和宿主共享的操作、纯文本及准确修订。Ulysses 用于信息层级、文稿组织和逐步收起导航的参考。

当前模型与原生 `gpt-6.2-sol` / `xhigh` 讨论后采用以下范围：

- 完整稿名在正文标题出现一次；工具栏常显所读修订、采用状态及旧版身份。旧版仍可能是采用稿，不能混淆最新修订和章节采用版本。
- 文稿列表保留一幕一条、准确原文摘要及来源版本，减少同一范围内重复的章节和长元信息。继续使用现有搜索和读取策略。
- 比稿突出双方的准确身份与增删，采用前明确稿件版本、目标场景和原采用稿，保留回执与并发冲突核对。
- 本版已确认依据、场景可用资料和下一稿写作准备分别说明。界面组合不能改变历史依据。
- 不以拖拽四栏、强制项目隔离、四标签检查器或更换编辑器作为本轮完成条件。排版偏好、全库快搜、写作目标和复杂导出需新的使用证据，不捆绑实施。

## 审查跟进

- R1：主代理和讨论席查看真实 1280px、WebKit 320px 页面后确认标题与版本层次改善。独立代码审查发现 ScenePage 没有传递场景名；主代理补上，并用有归属的场景与未归属的空场景验证手机版本菜单。专项 1/1 通过。
- L1：初稿元信息双列在章内无上下文时挤窄唯一状态，主代理要求改为单列。最终保留原状态字符串，避免建立重复的展示数据结构；没有改数据读取和摘要版本算法。实施定向 10/10，最终整合另验。
- E1：独立审查指出读取失败不能显示“没有已确认依据”，以及条件渲染的描述节点不能留下无效 ARIA 引用。这两项作为集成前修复要求，最终结果随后记录。
- C1：确认动作提前后，原采用稿身份也必须出现在动作之前；长正文核对仍可按需展开。不同视口的采用测试使用独立场景，避免第一轮写入污染后续断言。

E1 两项问题已修复并获独立复核；主代理另从真实 Frame 图发现空态说明重复，改为只显示一份并关联该描述节点。依据关联测试同时核对详细来源和顶部关联状态；Frame 测试从已移除的独立修订节点迁移到完整标题/修订文本及身份行边界。两处更新经独立核对，没有删除版本、关联 ID、来源原文或面板尺寸断言。
